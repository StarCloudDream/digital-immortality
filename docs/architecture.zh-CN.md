## 分层职责

| 层 | 模块 | 是否核心 | 谁来维护 |
|---|---|---|---|
| 采集层 | `sinian/adapters/*` | ❌ 插件 | 社区：任意平台、任意导出方式 |
| 侧写层 | `sinian/core/profiler.py` + `life.py` | ✅ | 核心团队 |
| 人格层 | `sinian/core/persona.py` | ✅ | 核心团队 |
| 模拟层 | `sinian/core/simulator.py` + `llm.py` | ✅ | 核心团队 |
| 延续层 | `sinian/core/curiosity.py` | ✅ | 核心团队（信息源是插件） |
| 质量层 | `sinian/core/evaluator.py` | ✅ | 核心团队 |
| 证据层 | `sinian/core/evidence.py` | ✅ | 核心团队 |
| 治理层 | `sinian/core/versions.py` + `inquiry.py` | ✅ | 核心团队 |
| 接入层 | （未来）bots / 纪念页 | ❌ 插件 | 社区 |

核心只对一条主链负责：**统一消息 → 人格档案 → 模拟对话**。
两端都是插件：历史怎么进来，对话怎么出去。

## 数据流

```
聊天记录（任意平台）
   │  adapter.fetch() —— 流式产出，is_self 必须准确
   ▼
统一消息流
   │  extract_windows(window=10) —— 以本人发言为锚点
   ▼
ContextWindow[]（本人发言 ± N 条上下文，跨会话不串台）
   │  统计侧写 + 生活侧写（免费）→ LLM 侧写（可选）
   ▼
断言仓库（ClaimStore）—— 每条结论都是带置信度、出处、时间戳的断言；
   证据跨轮次累积，矛盾断言竞争，低于阈值保持"未知"（增量侧写由此自然成立）
   ▼
人格档案（身份/风格/生活/关系/知识/自定义层）
   │  身份设定覆盖 · 风格意向在学习前引导
   ▼
persona.json（可读 · 可改 · 可传承）
   │  build_system_prompt()
   ▼
LLMProvider（Ollama 本地 / OpenAI 兼容云端）
   ▼
这个人在说话——好奇心引擎让 TA 跟上新的世界
```

主链之外，治理层缠了两道保险：`PersonaVault` 给每份快照登记指纹，
被篡改的存档拒绝回滚；非对称权限梯度让任一方一票即可暂停人格，
恢复则必须留痕。`inquiry.py` 从另一头闭上回路——档案哪里是糊的，
它去问活人，而不是瞎猜。

## 关键设计决策

1. **适配器只吐流，不落地**：`fetch()` 返回 Iterator，几十万条消息不爆内存。
2. **统计先行，LLM 补充**：任何可数的东西（口头禅、节奏、活跃时段）
   绝不浪费 token；LLM 只做统计算不了的：速写、气质、细腻处。
3. **锚定上下文**：分析单元是一条本人发言 ± 前后各 N 条。
   别人怎么接你的话，比你孤立的单句更能说明你是谁。
4. **LLM 可换**：`LLMProvider` 抽象，本地优先（隐私），云端兼容协议兜底。
   `httpx` 是可选依赖。
5. **人格档案是纯 JSON**：可读、可手改、可版本管理。
   自定义层让它可扩展——人比任何模板都复杂。
6. **诚实在 prompt 层面强制执行**：知识边界和"不知道也是有效答案"
   写进每一个 system prompt。
7. **评估器是回归守门员**：任何对侧写或 prompt 组装的改动，
   都必须守住"像不像 TA"的分数。
8. **每个属性都是断言，不是事实**：结论带置信度、出处、时间戳。
   矛盾断言竞争而不是被静默覆盖；低于阈值保持"未知"——
   档案像人一样慢慢长大，而不是一次定型。

## 待社区实现（按优先级）

1. 事实性记忆（RAG）：记得*发生过什么*，而不只是*怎么说话*
2. 好奇心信息源插件：RSS / 新闻 API / 定时抓取（接口见 `curiosity.py`）
3. 跨年份的人格快照（增量侧写本身已由断言仓库的跨轮次累积实现）
4. 评估器 v2：embedding 相似度 + LLM-as-judge 双盲打分
5. 各国聊天软件适配器 + 接入层插件（纪念页、聊天机器人、语音）
